# Отчёт: «Амба» — AI-ассистент путешествий по Приморью

## Соответствие критериям задания

| Критерий оценки | Статус | Где смотреть |
|---|---|---|
| **Работает end-to-end** — от ввода до готового плана | ✅ | `make dev` → запрос → план + карта; e2e-тесты в Chromium (`e2e/`) |
| **Это агент** — тулы и цикл, а не один вызов LLM | ✅ 10 тулов + `ask_user` + `submit_plan` / `decline_request`, цикл до 12 шагов, параллельные вызовы, цикл исправлений | `backend/app/agent.py` |
| **Есть замеры** — минимум две версии | ✅ 3 версии × 20 запросов, автоматический прогон | `eval/`, `eval/results/summary*.md` |
| **Команда объясняет**, как повторить | ✅ README, слайд «Как повторить», Makefile | `README.md`, презентация |

Пять требований к решению:

1. **Агентная логика** — свой цикл на OpenRouter tool calling: системный промпт → выбор тула → вызов → результат агенту → сборка плана по JSON-схеме → сверка → при противоречиях возврат агенту.
2. **Веб-фронт** — запрос → план; бонус: карта маршрута на OpenStreetMap (Leaflet), маршрут по дорогам на каждый день, АЗС.
3. **Деплой** — Dockerfile, docker-compose, `deploy/deploy.sh user@IP` (нужен доступ к VM, см. ниже).
4. **Eval** — 20 фиксированных запросов (15 поездок, 5 нецелевых), качество / токены / $ / время, сравнение v1–v3.
5. **Guardrails** — пред-фильтр (другие регионы, prompt injection, оффтоп) + `decline_request` + проверка региона по координатам. Все 4 примера со слайда задания входят в эвал.

Обязательный реальный источник данных: подключено **пять** — Open-Meteo, OSRM, Nominatim, OSM Overpass, Википедия.
Без открытого API — офлайн-датасеты: 41 место с режимом работы, жильё, расписания, события, наличие топлива.

## Дизайн и необычный формат ответа

**Обычный вид — современный** (сделан по гайду плагина frontend-design). Тема — утренний туман над Японским морем:
туманно-голубой фон, глубокий морской для текста, тигриный оранжевый только для главного действия и маршрута;
шрифты Unbounded (заголовки) и Onest (текст). Главный акцент — Амба выглядывает из-за поля запроса.
План — таймлайн по дням, сверка — одна строка-статус, раскрывается списком; справа карта и шаги агента вживую.

**Вид «Бортовой журнал»** (переключатель «План / Бортовой журнал») показывает тот же план в морском стиле Приморья:
сетка морской карты, компас, координаты каждой точки, отметка «Маршрут проверен». Текст обычный и понятный всем.

**Ссылки, чтобы всё оформить:** у каждого места и кафе — Яндекс Карты и сайт заведения, у рейсов — Яндекс Расписания с датой
(там же билеты), у ночёвки — гостиницы рядом. Ссылки строит сервер, модель их не выдумывает.

**Еда:** реальные кафе и рестораны из OpenStreetMap (тул `find_food`) с кухней, часами работы и сайтом.

**Диалог:** если в запросе не хватает важного (кухня, бюджет, темп), агент один раз задаёт 1–2 вопроса с готовыми вариантами;
ответ можно пропустить.

**Маскот** — амурский тигрёнок **Амба** в мурмолке с гусиным пером и свитком (SVG, `frontend/assets/amba.svg`).
В приложении он в шапке и на главном экране, пишет пером, пока агент работает, грустит при отказе. В презентации — на титуле, в команде и на финале.
Палитра: ночное Японское море, пергамент, киноварь, сусальное золото, тигриный оранжевый.

## Отладка: что нашли и починили

| Баг | Исправление |
|---|---|
| «поездить» распознавалось как «поезд» | границы слов в регулярке транспорта |
| «сочинение» ловилось как «Сочи», «натуральный» — как «Урал» | `\b` для коротких названий регионов |
| «Хасанский район» привязывался к селу Хасан → всего 3 места | самое длинное совпадение в справочнике + районы |
| Поиск по городу терял остров Русский и сафари-парк | фильтр по району включается только для районов и округов |
| Пустые дни плана не считались ошибкой | проверка `non_empty_days` |
| Подъём на Пидан в 14:30 заканчивался в темноте | проверка по **времени окончания** визита и закату |
| Нижняя часть свитка не рисовалась на длинных планах | `filter: drop-shadow` на высоком элементе упирался в лимит GPU → `box-shadow` |
| Титло (U+0483) квадратиками во многих шрифтах | титло рисуется CSS-ом (`overline wavy`) |
| «ъ» приписывался к «мм», «дн.», «АЗС» | список сокращений и аббревиатур |
| Overpass часто отвечает 502/таймаутом → +9 с на запрос | предохранитель: при сбое 10 минут используется офлайн-список АЗС |

## Эвал

10 запросов из набора (7 поездок разными видами транспорта и 3 нецелевых), три версии пайплайна:

| Вариант | Модель | Качество | Тул верный | Интент (сверка) | План сходится | Guardrails | Токены / запрос | $ / запрос | Время, с (ср / p50) |
|---|---|---|---|---|---|---|---|---|---|
| v1 · Бейзлайн | `minimax/minimax-m3.1-flash:free` | **0.64** | 70% | 0.55 | 43% | 67% | 87 860 | 0.0000 | 68.47 / 67.03 |
| v2 · Сжатие контекста + сверка | `minimax/minimax-m3.1-flash:free` | **0.75** | 80% | 0.57 | 57% | 100% | 52 098 | 0.0000 | 65.65 / 65.07 |
| v3 · Финальная: v2 + исправления + DeepSeek | `deepseek/deepseek-v4.1-flash` | **1.00** | 100% | 1.00 | 100% | 100% | 32 462 | 0.0052 | 50.54 / 22.79 |

- **v1 → v2:** сжатие контекста срезало токены с 88 до 52 тыс. на запрос (−41%), фильтр поднял точность отказов с 67% до 100%.
- **Эвал нашёл три бага агента:** план не влезал в `max_tokens` и обрезался; модель присылала `days` строкой JSON; на невыполнимый запрос (170 км на велосипеде за день) агент бесконечно собирал данные. Всё исправлено и покрыто тестами.
- **v3** (исправления + DeepSeek V4.1 Flash): 100% планов сходится, 32 тыс. токенов и $0.005 на запрос, медиана 23 с.
- v1 и v2 гонялись на бесплатной MiniMax M3.1 Flash: на ключах почти нет баланса.
